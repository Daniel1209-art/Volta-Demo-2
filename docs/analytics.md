# VOLTA — аналитическая схема

Что бэкенд пишет в SQLite для будущего дашборда. Дашборда и API ещё нет:
этот слой только копит факты, историю до момента внедрения восстановить нельзя.

## Определения метрик (зафиксированы, менять только явным решением)

* **Метрики уровня раунда** — максимальный множитель, средний множитель, RTP.
  Считаются по `rounds.crash_point` — глобальному крашу, одинаковому для всех
  игроков раунда. Личный множитель лампы сюда не входит.
* **Метрики уровня ставки** — решение конкретного игрока. Метрика «личный
  множитель при фиксации против финала раунда» = `bets.cashout_mult` против
  `bets.crash_point` той же строки.
* **Периоды 1д / 7д / 1м** — скользящие окна от текущего момента (24 ч,
  168 ч, 30 суток), не календарные сутки/недели/месяцы.
* **Реальные игроки** — строки с `is_bot = 0`.
* **Процент использованных переключений** = `switches_used / MAX_SWITCHES`
  (MAX_SWITCHES = 4). Бесплатное включение лампы на старте раунда
  переключение не тратит и в `switches_used` не входит.

## Таблицы

### `rounds` — раунд целиком
`round_id, hash, seed, crash_point, crashed_at, client_seeds, seed_mode`

`crash_point` хранится ×100 целым; **0 означает мгновенный краш ×1.00**.
`seed_mode`: `multi` — в раунде были ставки реальных игроков, их client seed-ы
вошли в расчёт; `single` — реальных ставок не было, использован системный seed.

### `bets` — итог ставки, по строке на игрока за раунд
Пишется один раз, в момент краша.

| столбец | смысл |
|---|---|
| `amount`, `payout`, `win` | сумма, выплата, выигрыш/проигрыш |
| `final_mult` | итоговый множитель выплаты (накопленный лампой `persAccum`) |
| `cashout_mult` | **глобальный** множитель в момент последнего OFF; `NULL` — игрок не выключал |
| `crash_point` | краш раунда, скопирован в строку: метрика «фиксация против финала» не должна ломаться, когда раунд выпадет из retention раньше ставки |
| `switches_used` | из 4; бесплатный старт не считается |
| `on_count`, `off_count` | сколько включений (кроме бесплатного) и выключений за раунд |
| `had_off` | был ли хотя бы один OFF — для метрики «% раундов с хотя бы одним OFF» |
| `auto_bet` | ставка сделана при включённом автопилоте |
| `auto_switches` | сколько из переключений раунда выполнил автопилот |
| `session_id`, `is_bot` | связь с сессией; признак бот-трафика |
| `day` | календарный день в `RESET_TZ` — только для суточной «My Game History» на клиенте |

### `lamp_events` — сырая последовательность переключений
`round_id, player_id, session_id, seq, lamp_on, mult, src, at`

Пишется в момент события: порядок ON/OFF задним числом не восстановить.
`seq` — номер события внутри раунда у игрока. `src`: `free` (бесплатное
включение на старте), `manual` (кнопка игрока), `auto` (автопилот).
Столбец назван `lamp_on`, потому что `ON` — зарезервированное слово SQLite.

### `sessions` — игровая сессия, ЛОГИЧЕСКАЯ
`player_id, started_at, last_seen_at, ended_at, ip_hash, country, region, is_bot`

Несколько ws-соединений одного игрока (вкладки, переподключения) в пределах
`SESSION_IDLE_MS` склеиваются в одну строку: иначе перезагрузка страницы и
обрыв мобильной сети дробили бы «время в игре». `ended_at IS NULL` — сессия
идёт; возврат в окно склейки снимает `ended_at` обратно. Оборванные без
`close` соединения закрываются фоновой чисткой по `last_seen_at`.
Время в игре = `COALESCE(ended_at, last_seen_at) − started_at`.

## IP и гео

Сырой IP **не хранится нигде** и не покидает обработчик соединения.

* `ip_hash` = `SHA256(соль + IP)` — различает уникальных посетителей и
  повторные визиты, обратно в адрес не разворачивается. Соль генерируется один
  раз в `data/.ip_salt` (0600) или задаётся `IP_SALT`. Потеря соли рвёт связь
  со старыми хешами, игровых данных не касается.
* `country` / `region` — офлайновый CSV-диапазонник, путь в `GEOIP_CSV`
  (по умолчанию `data/geoip.csv`). Поддерживаются форматы DB-IP lite:
  `start,end,country` и city-уровень `start,end,continent,country,region,city`.
  IPv4 и IPv6 приводятся к одной 32-символьной hex-шкале, поиск —
  бинарный по отсортированным диапазонам.
* **Файла нет → `country`/`region` остаются `NULL`**, всё остальное работает.
  Чтобы география заполнялась, CSV нужно положить на сервер и обновлять
  (DB-IP публикует lite-версию ежемесячно, CC-BY 4.0).

Гео определяется по первому наблюдению сессии и при переподключении не
перезаписывается (`COALESCE`).

## Срок хранения

`RETENTION_DAYS` (по умолчанию 35) — окно дашборда «1 месяц» плюс запас.
Чистка раз в 10 минут удаляет `bets`, `rounds`, `lamp_events`, `sessions`
старше срока. Раньше ставки резались по календарному дню, а раунды — до
последних 600 (≈4 часа), поэтому окна длиннее суток были нерасчитуемы.

Суточный сброс «My Game History» на чистку не завязан: клиентская выборка
отбирает строки по `day = сегодня`, а не полагается на удаление вчерашних.

## Переменные окружения

| переменная | по умолчанию | назначение |
|---|---|---|
| `RETENTION_DAYS` | `35` | срок хранения аналитики |
| `SESSION_IDLE_MS` | `1800000` (30 мин) | окно склейки сессии |
| `GEOIP_CSV` | `data/geoip.csv` | гео-диапазонник |
| `IP_SALT` | из `data/.ip_salt` | соль хеширования IP |

## Открытые вопросы к API-слою

* **RTP** уровня раунда — теоретический (из распределения crash-point, одно
  число, от окна не зависит) или фактический `SUM(payout)/SUM(amount)`?
  Разные источники данных, определение пока не зафиксировано.
* **`is_bot` сейчас всегда 0.** Боты-заполнители стола живут только в памяти
  (`spawnBots`) и в БД не попадают, поэтому `sessions`/`bets` по определению
  содержат только реальный трафик. Флаг заведён, чтобы контракт дашборда не
  менялся, если источник бот-трафика появится позже; проставлять его надо в
  `openSession` и в записи ставки — это единственные два места.
