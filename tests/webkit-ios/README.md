# WebKit-проверки под iOS Safari

Движок WebKit — то же ядро, что в Safari на iPhone. Chrome/Chromium ловит
не все iOS-специфичные баги (autoplay-политика звука, локаль десятичного
разделителя, поведение кастомных чекбоксов), поэтому эти сценарии гоняются
именно на WebKit с iPhone-вьюпортом и локалью `ru-RU` (запятая как
десятичный разделитель).

Тесты **не входят** в деплой: `deploy/deploy.sh` ставит зависимости только
в `backend/`, сюда не заглядывает.

## Запуск

```bash
cd tests/webkit-ios
npm install
npx playwright install webkit
node autopilot.js                       # против прода
TARGET=http://localhost:8097 node autopilot.js   # против локальной сборки
```

Скрипт завершается кодом `1`, если проверка не прошла.

## Что покрыто

| Файл | Проверяет |
|---|---|
| `autopilot.js` | Ступени автопилота, введённые **с запятой** (`1,10`), корректно парсятся и лампа реально переключается на этих множителях. Регрессия на баг: `type="number"` на RU-локали iOS отдавал пустой `value` → `parseFloat` = NaN → все ступени молча отбрасывались. |

## Важно: это приближение, а не гарантия

Playwright WebKit ≠ Safari на реальном iPhone. Он не воспроизводит
аппаратный mute-переключатель, реальную autoplay-политику по жесту и
версии iOS < 16.2 (где нет `color-mix()`). Финальную проверку звука и
касаний всё равно делаем на живом устройстве.
